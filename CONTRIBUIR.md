# Como contribuir

Este estudo pretende ser escrutinado. As críticas, sobretudo de quem discorda, são bem-vindas.

## Formas de contribuir

| Quero… | Como |
|---|---|
| Contestar um pressuposto (um custo, uma taxa, uma capacidade, uma data) | Abrir uma issue com o modelo **«Contestar um pressuposto»** |
| Propor um cenário completo para ser corrido no modelo | Abrir uma issue com o modelo **«Propor cenário»**. Quando estiver publicado, usar também o modelo de folha de cenário |
| Reportar um erro (no código, num número ou no texto) | Abrir uma issue com o modelo **«Reportar erro»** |
| Discutir método, resultados ou interpretação | GitHub Discussions, quando estiverem ativas |
| Contribuir com código | Pull request com testes. Ver as regras abaixo |

## Regras para contestar números

- **Indique a fonte:** documento, página ou tabela, e a citação literal. Prefira fontes oficiais, europeias, intergovernamentais ou revistas por pares.
- **Indique a unidade e o ano monetário** (por exemplo, € de 2024 por kW).
- **Diga, se possível, que efeito espera nos resultados.**

Um número sem fonte verificável não pode entrar no modelo, venha de quem vier, incluindo do autor.

## Que resposta vai ter

Cada contributo recebe uma resposta pública de um de três tipos:

1. **Aceite:** a alteração é feita e o seu efeito nos resultados é indicado.
2. **Rejeitado:** com a razão.
3. **Adiado:** fica para uma versão seguinte (por exemplo, a 1.1).

Quem encontrar um erro que mude uma conclusão é agradecido no relatório.

## Cenários propostos por terceiros

Os cenários completos e válidos são corridos **exatamente como propostos** e publicados, com a indicação de quem os propôs:

- as primeiras 4 propostas recebidas até 6 de novembro de 2026 entram na versão preliminar;
- até mais 4, recebidas até 27 de novembro, entram na versão 1.0;
- as restantes entram na versão 1.1.

## Contribuições de código

- Todas as alterações passam pela integração contínua: testes, esquemas das tabelas e verificação de fontes.
- **Nenhum número literal no código.** Os valores vêm da tabela de pressupostos, com fonte.
- As alterações ao modelo devem incluir um teste. Sempre que possível, um caso pequeno com resposta conhecida.

## O que não enviar

- Dados confidenciais ou sem autorização de redistribuição.
- Dados pessoais.
- Credenciais ou chaves de acesso.
